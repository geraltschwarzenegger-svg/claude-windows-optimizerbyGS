# Проверки v2

Скрипт не требует Pester или сторонних модулей. Из корня репозитория:

```powershell
powershell -NoProfile -File .\tests\Test-V2.ps1
powershell -NoProfile -File .\tests\Test-Menu.ps1
```

На Linux с установленным PowerShell:

```sh
pwsh -NoLogo -NoProfile -File ./tests/Test-V2.ps1
pwsh -NoLogo -NoProfile -File ./tests/Test-Menu.ps1
```

Проверяются синтаксис обеих версий и комплектного Device Tweaker, неизменность исходного CMD, подтверждения Auto/QOL, контроль длины загрузки и ранний выход режима проверки. Функции загружаются через AST отдельно; полный PowerShell-код запускается только в дочернем процессе с `LLC_RUN_CHECK=1`. В Linux ожидается код `2`, поскольку системные настройки требуют Windows PowerShell 5.1.

Поиск файлов проверяется на настоящих временных каталогах: два комплектных ресурса находятся рядом с CMD, копии в `Resources` имеют приоритет, отсутствующие файлы сохраняют ожидаемый путь, посторонние файлы и каталоги вместо файлов не используются. Проверяются разделители `/` и `\`. Временные файлы содержат только текстовые метки, приложения не запускаются.

Запуски CMD `/help` и `/check` выполняются только в Windows; на Linux они отмечаются как пропущенные. Тесты не применяют настройки Windows, не скачивают драйверы и не проверяют поведение железа или прирост производительности.

`Test-Menu.ps1` отдельно проверяет навигацию и значения пунктов, границы кадров в окнах от `0×0` до `180×60`, прокрутку и изменение размеров, обрезку длинных строк и Unicode. Модель терминального буфера применяет настоящий ANSI-вывод нескольких кадров подряд: старые строки должны очищаться, выделение остаётся единственным. Это моделирование экрана; реальный ввод с клавиатуры и классический Windows renderer требуют проверки в терминале.

Полный PowerShell-код меню запускается в дочернем процессе только как `/demo /snapshot`; проверяется соответствие кадру `80×30` и отсутствие журнала системной инициализации. CMD-обёртка этого режима проверяется в Windows и пропускается в Linux. Режим demo завершает выполнение до проверок ОС, создания журнала и вызовов настроек Windows.

В `Test-V2.ps1` также проверяется подключение NVPI-R: XML читается с объявленной кодировкой, сохранены 43 глобальные настройки и значения ReBAR; запуск GUI не импортирует профиль; Merge получает корректно заключённый в кавычки путь с пробелами; отсутствующие файлы и ошибки процесса обрабатываются; Auto пропускает импорт без NVIDIA. `Start-Process` заменён stub-функцией: EXE и NVAPI не запускаются. Код выхода 0 при импорте остаётся предупреждением, поскольку NVPI-R не возвращает надёжный результат применения.

## Exovance Device Tweaker v2

Из корня проекта: `pwsh -NoLogo -NoProfile -File ./tests/Test-DeviceTweakerV2.ps1` (Windows: `powershell.exe -NoProfile -File .\tests\Test-DeviceTweakerV2.ps1`). Проверяются 64-битные маски, топология и границы RSS, точный backup через JSON, отказ записи/rollback, zero-mask reset и подключение меню. Реестр подменяется в памяти. На Windows дополнительно компилируется встроенный WinForms C#; окно не запускается.

Тема и индикация Exovance: `pwsh -NoLogo -NoProfile -File ./tests/Test-DeviceTweakerUI.ps1`. Проверяются реальные цветовые функции приложения, контраст, отдельные selected/hover-состояния и запрет успешной индикации при ошибке. Окно не запускается.

## Журналы Device Tweaker v2

`pwsh -NoProfile -File ./tests/Test-DeviceLogs.ps1` (Windows: `powershell.exe -NoProfile -File .\tests\Test-DeviceLogs.ps1`) проверяет 19 сценариев на временных файлах и подменённом реестре: отдельные сеансы, владение последней сводкой, архивирование старого лога, отмену и частичную ошибку, реальные функции записи affinity/priority, различение отсутствия и нуля, виртуальные адаптеры, сравнение до/после, сохранение причины ошибки, UTF-8/JSONL, отказ диска, ошибки фонового writer и очередь исключений интерфейса. Отдельно проверяется расшифровка масок с CPU 31/32/63. Окно не создаётся, настройки устройств не записываются. Проверки включены в оба задания CI.

## Определение ветки GPU

`pwsh -NoProfile -File ./tests/Test-GpuRegistry.ps1` (Windows: `powershell.exe -NoProfile -File .\tests\Test-GpuRegistry.ps1`) проверяет 11 сценариев: присутствующие PCI-адаптеры и CIM fallback, NVIDIA/AMD на разных индексах, несколько GPU, неверную/отсутствующую ветку, отмену и смену Driver во время выбора, ошибки записи и неизменность имён/значений/типов/порядка всех четырёх исходных GPU-пресетов. PnP, реестр и функции записи подменяются; реальные настройки не меняются.
