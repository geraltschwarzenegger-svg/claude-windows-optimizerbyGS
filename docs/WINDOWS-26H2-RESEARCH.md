# 🔎 Windows 11 26H2 — предварительное исследование

**Дата проверки: 1 ноября 2026 года.**

Статус выпуска Windows 11 26H2, номер её сборки и изменения платформы в этой сессии **не подтверждены официальными источниками**. Ни оригинальный CMD, ни v2 нельзя на основании этого исследования объявлять адаптированными к 26H2.

[← README](../README.md) · [Сравнение оригинала и v2](COMPARISON.md) · [Исходник v2](../Low-Latency-Corp-Menu_v2.cmd)

## Что удалось проверить

Выполнен локальный аудит существующего CMD: проверены определение ОС, ограничения по сборкам, политики QOL, список служб, работа с привилегиями и пути драйверов. Системные настройки не применялись. Windows VM и образ 26H2 в распоряжении этой проверки отсутствуют.

Доступ к `learn.microsoft.com` завершился отказом `CONNECT 403` по сетевой политике. Попытки чтения `MicrosoftDocs/windows-itpro-docs` через raw URL и Git вернули `404`. Эти ответы описывают доступ к конкретным адресам; они **не доказывают ни наличие, ни отсутствие 26H2**.

Приоритетные политики для сверки: `ConfigureSearchOnTaskbarMode`, `TurnOffWindowsCopilot`, `HideRecommendedSection`, `DisableWindowsConsumerFeatures`, `AllowNewsAndInterests`. Успешная запись значения реестра не доказывает, что Windows применяет политику.

В списке отключаемых служб есть `umbus`, `CompositeBus`, `vid`, `vdrvroot`, `NdisVirtualBus`, `luafv`. Их нельзя автоматически объявить подходящими для отключения в новой версии. Аналогично `HwSchMode`, MMCSS, сетевые параметры и GPU-твики требуют проверки оборудования и драйвера.

## Данные системы для сопоставления

Следующая команда в Windows PowerShell только читает сведения об ОС. Она не запрашивает имя компьютера, пользователя, серийный номер или ключ продукта и не меняет настройки:

```powershell
$cv = Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion'
$os = Get-CimInstance Win32_OperatingSystem
$cpuArchitectures = @(Get-CimInstance Win32_Processor | Select-Object -ExpandProperty Architecture -Unique)
[pscustomobject]@{
    DisplayVersion = $cv.DisplayVersion
    Build          = '{0}.{1}' -f $cv.CurrentBuildNumber, $cv.UBR
    Edition        = $cv.EditionID
    CPUArchitectureCodes = $cpuArchitectures -join ','
    OSArchitecture = $os.OSArchitecture
    ProductType    = $os.ProductType
}
```

`ProductType = 1` обозначает рабочую станцию; сервер нельзя определять только по большому номеру сборки. Коды CPU: `0` — x86, `9` — x64, `12` — ARM64. Архитектуру ОС нужно отличать от разрядности процесса PowerShell. Само значение `DisplayVersion` также необходимо сверить с официальным соответствием сборки.

## Критерии адаптации

1. Подтвердить официальное название, статус, сборку и архитектуры релиза; отдельно учитывать Insider и общедоступный выпуск.
2. Проверить применимость каждой используемой политики к версии и редакции, не ограничиваясь наличием ключа реестра.
3. Добавить раннюю проверку идентичности ОС до transcript, native initialization и TrustedInstaller. Неизвестные сочетания должны оставаться в диагностическом режиме.
4. Проверить службы, драйверные пакеты, API интерфейса, Explorer, Start/Search и OneDrive; не переносить их поведение автоматически с 24H2.
5. Реализовать изменения отдельным CMD, сохранив оригинал и v2; описать исключённые или неподтверждённые действия.
6. Проверить новую логику тестами и выполнить выбранные действия в Windows VM соответствующей версии, включая повторный вход, перезагрузку и восстановление исходного состояния.

До выполнения этих условий нельзя утверждать, что весь набор настроек поддерживает 26H2. Статический разбор PowerShell в Linux не заменяет испытания Windows.
