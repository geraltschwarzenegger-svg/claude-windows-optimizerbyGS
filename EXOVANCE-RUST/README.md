# Exovance Rust 0.1 — предварительная версия

Отдельный консольный интерфейс Exovance на Rust. Существующий CMD остаётся рабочей версией. Это первый этап переноса: **интерфейс и управление схемами питания реализованы на Rust; остальные операции Windows выполняет встроенный код Windows PowerShell 5.1**. Приложение не выдаёт этот этап за полную замену всех алгоритмов на Rust.

## Что уже работает

- Все 20 выбираемых пунктов главного CMD, включая выход, сохранены. Все вложенные меню существующих разделов, выбор адаптеров, вопросы и подтверждения передаются Rust-интерфейсу через JSON. Навигация автозагрузки также перенесена с сохранением функций изменения записей.
- Графитовый интерфейс с бирюзовым выделением, прокрутка, адаптация к размеру окна, Enter/Esc, Home/End, PgUp/PgDn. F1 открывает русскую справку с назначением, действием, путями и реестровыми значениями из действующего меню. Enter внутри справки только закрывает её.
- Native Rust-раздел схем питания читает список и активный GUID, экспортирует схему, импортирует/активирует Exovance и открывает панель Windows. Перед активацией сохраняется отдельный `power-before-<ID>.pow`; отсутствие backup останавливает применение. Установленной схеме обновляются имя/описание без повторного импорта параметров. Активный GUID проверяется командой Windows.
- Журналы каждого рабочего запуска: `logs/rust/<время-ID>/report.txt`, `events.jsonl`, `output.txt`, `powershell.txt`. Уровни ошибок приходят от результатов операций, а не поиска произвольного слова `failed` в названии устройства. Нулевой код движка не представляется проверкой успеха каждого действия.
- Исполняемый код меню и PowerShell-часть находятся внутри EXE; отдельный `.cmd` при запуске Rust-версии не нужен. Внешние программы, профили и файлы схем питания остаются в комплекте.

## Запуск

Поместите `Exovance.exe` в корень существующего комплекта рядом с папками `Resources`, `DEVICE-TWEAKER-V2` и `POWER-PLAN`. Обычный запуск без повышения прав открывает режим просмотра. Для работы откройте терминал администратора и запустите EXE. Каталог с ресурсами также можно задать явно:

```powershell
.\Exovance.exe --root 'C:\Tools\Exovance'
```

Для просмотра интерфейса без применения и без повышения прав:

```powershell
.\Exovance.exe --demo
.\Exovance.exe --snapshot
.\Exovance.exe --check
.\Exovance.exe --list
.\Exovance.exe --help
```

Эти режимы не применяют настройки. `--demo`, `--snapshot` и `--list` не запускают PowerShell и не создают логи. `--check` в Windows запускает только существующую раннюю проверку синтаксиса/среды, до системной инициализации; в другой ОС возвращает код 2. `--demo` и `--snapshot` работают также в Linux. Деморежим показывает интерфейс и описания разделов; реальные вложенные меню и оборудование доступны при рабочем запуске в Windows.

Windows 10/11 x64 и Windows PowerShell 5.1 нужны для изменения настроек. В Windows CI EXE собирается MSVC со статическим CRT: пользователю не нужен Rust/Cargo и отдельная установка Visual C++ Runtime для самого меню. Внешние приложения сохраняют собственные требования.

## Сборка и проверки

Из каталога `EXOVANCE-RUST` с актуальным стабильным Rust (не ниже 1.88):

```powershell
cargo build --release --locked
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
powershell -NoProfile -File .\tools\Export-Catalog.ps1 -Check
powershell -NoProfile -File .\tools\Test-Bridge.ps1
```

В Linux для PS-проверок используйте `pwsh`. Сборка читает актуальный `../Low-Latency-Corp-Menu_v2.cmd`, проверяет ожидаемые границы и встраивает прежние функции/таблицы. При изменении разделов CMD обновите каталог командой `./tools/Export-Catalog.ps1`. Каталог и справка генерируются из деклараций через AST; системный код при этом не запускается.

14 Rust-тестов проверяют навигацию, Unicode/размеры кадров, протокол, сохранение пунктов и команды схем питания; powercfg подменён тестовым исполнителем. Пять проверок PS дополнительно запускают настоящие дочерние процессы через JSON pipes: отмена Auto, типы значений, Unicode, подменённая автозагрузка, неверный ID, выбор заголовка и разрыв связи. Проверяются синтаксис встроенного PS и неизменность исходных функций/пресетов. Ни одна из этих проверок не применяет системные настройки. В GitHub Actions предусмотрены Linux и Windows PowerShell 5.1, MSVC-сборка и скачиваемый артефакт EXE.

## Текущие границы переноса

Это рабочий предварительный вариант, а не подтверждение совместимости каждого твика с вашим ПК. Device Tweaker остаётся отдельным WinForms-инструментом. GPU/IRQ/RSS-пресеты, `Unlimited`, профили NVIDIA и широкие операции Auto/QOL не переписывались в этой итерации: применяются прежними функциями. Подтверждения Auto/QOL сохраняются; меню не запускает оптимизацию при открытии. Предварительный запуск TrustedInstaller из старого основного цикла удалён из Rust-варианта; существующие разрешения/обходы доступа запрашиваются соответствующими действиями при необходимости.

Общего полного rollback всех операций меню по-прежнему нет. Ctrl+C во время работы завершает дочерний PowerShell, но уже выполненные записи и запущенные отдельные приложения автоматически не откатываются. После прерывания проверьте журнал. Журналы могут содержать пути и имена устройств; ответы на запросы ввода Rust самостоятельно не записывает, но прежний transcript PowerShell может содержать сведения, напечатанные самими операциями.

Будущий полный перенос означает отдельную реализацию и проверку реестра, служб, SPI/QOL, профилей пользователей и аппаратных функций в Rust. Подключение старой функции через интерфейс не считается её переписыванием.

Происхождение встроенной логики: действующий `Low-Latency-Corp-Menu_v2.cmd` этого репозитория; сведения о внешних инструментах и оригинальном Device Tweaker сохранены в документации/`DEVICE-TWEAKER-V2/CREDITS.md`.

## Проверка файла Power Scheme Manager

`tools/Inspect-PowerSchemeManager.ps1 -Path 'C:\Tools\POWER-SCHEME-MANAGER.exe'` собирает версию, SHA256 и состояние Authenticode, не запуская сам EXE. Результат — небольшой JSON для сравнения с исходным релизом. Метаданные и подпись по отдельности не подтверждают корректность всех функций программы. Сам файл пользователя в эту сборку не включён.

Пакет Windows создаётся `tools/Package-Release.py`: EXE, уведомления о лицензиях, необязательные комплектные ресурсы и SHA256. Личные backup/logs из оригинального Device Tweaker исключаются. Если приложение распространяется без ресурсов, укажите полный существующий комплект через `--root`. Локальная кросс-сборка GNU и сборка MSVC в Windows CI различаются; точная цель и ограничения проверки указаны в `BUILD-INFO.txt` внутри ZIP.
